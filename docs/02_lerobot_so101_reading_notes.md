# LeRobot 与 SO-101 阅读笔记

日期：2026-07-12

## 1. 学习目标

理解完成一个真实具身智能机械臂项目所需的最小完整流程：

```text
机械臂连接
→ 标定
→ Leader-Follower 主从遥操作
→ 摄像头配置
→ 演示数据录制
→ 数据集检查
→ ACT 策略训练
→ 真实机械臂 Rollout
→ Agent 接入
→ 任务评估
```

## 2. LeRobot 的作用

LeRobot 提供一套统一的机器人学习工具链，覆盖：

- Robot 接口
- Teleoperator 接口
- Camera 接口
- Observation 与 Action
- Episode 录制
- LeRobotDataset
- Policy 训练
- Checkpoint 管理
- 真实机器人推理
- 任务评估
- Hugging Face Hub 集成

LeRobot 的核心价值是把不同机械臂、摄像头、数据集和策略统一到相对一致的软件接口中。

## 3. 核心概念

### 3.1 Robot

`Robot` 表示实际执行动作的机器人设备。

在本项目中，主要对应 Follower 执行臂。

典型职责：

- 建立连接
- 读取关节状态
- 读取夹爪状态
- 读取摄像头
- 接收动作
- 断开连接
- 进行安全检查

### 3.2 Teleoperator

`Teleoperator` 表示用于人工示教的控制设备。

在本项目中，主要对应 Leader 示教臂。

典型职责：

- 读取人工操作产生的关节位置
- 将 Leader 状态转换为 Follower 动作
- 支持演示数据录制

### 3.3 Observation

`Observation` 表示策略在当前时刻能够观察到的信息。

可能包含：

- Follower 关节位置
- Follower 夹爪状态
- 第一视角图像
- 第三视角图像
- 时间戳
- 任务信息

### 3.4 Action

`Action` 表示要发送给机器人的控制目标。

可能包含：

- 目标关节位置
- 夹爪目标位置
- 动作时间戳

LLM Agent 不直接生成高频 Action，Action 应由机器人技能、控制器或训练好的 Policy 生成。

### 3.5 Episode

`Episode` 表示一次完整任务演示或一次完整任务执行。

一次 Episode 通常包含：

- 任务开始状态
- 连续 Observation
- 连续 Action
- 摄像头图像
- 时间戳
- 任务描述
- 成功或失败结果
- Episode 结束标记

### 3.6 Policy

`Policy` 表示从 Observation 预测 Action 的策略模型。

本项目第一阶段使用 ACT 行为克隆策略。

### 3.7 Rollout

`Rollout` 表示将训练好的 Policy 部署到真实机器人上连续执行动作的过程。

真实 Rollout 风险较高，必须低速、有人监督，并保留紧急停止方式。

## 4. Leader 与 Follower

### 4.1 Leader 示教臂

作用：

- 由人工直接操作
- 提供示范关节位置
- 作为 Teleoperator
- 生成演示动作

### 4.2 Follower 执行臂

作用：

- 执行 Leader 的目标动作
- 执行脚本动作
- 执行 Policy 输出动作
- 生成机器人状态 Observation

### 4.3 基本通信链路

```text
PC / Python / LeRobot
→ USB 总线舵机驱动模块
→ HX 系列总线舵机
→ 机械臂关节
```

### 4.4 主从遥操作链路

```text
人工移动 Leader
→ 读取 Leader 关节位置
→ 进行标定映射与限幅
→ 生成 Follower 目标动作
→ Follower 执行动作
```

## 5. 机械臂关节模型

预期从底座到末端包括：

1. `shoulder_pan`
2. `shoulder_lift`
3. `elbow_flex`
4. `wrist_flex`
5. `wrist_roll`
6. `gripper`

以上名称需要在收到厂商源码后进一步确认。

需要检查：

- 关节名称
- 舵机 ID
- 关节顺序
- 关节方向
- 最小角度
- 最大角度
- 零点
- 夹爪开合范围

## 6. 标定

### 6.1 标定目的

标定用于把舵机原始位置值映射为一致、可解释的关节坐标。

标定完成后应保证：

- Leader 与 Follower 对应关节方向一致
- Leader 与 Follower 对应关节范围一致
- 数据集中的关节值具有一致含义
- Policy 输出能够转换为有效动作
- 关节限位可用
- 夹爪开合映射正确

### 6.2 为什么成品机械臂仍需标定

即使机械臂已经组装完成，不同设备仍可能存在：

- 舵机零位差异
- 机械安装角度差异
- 关节方向差异
- 夹爪行程差异
- 结构件装配误差
- 舵机回差

因此厂商发货前测试不能替代本地标定。

### 6.3 到货后检查项

- Leader 串口
- Follower 串口
- 两台机械臂的设备名称
- 标定文件保存路径
- 初始姿态
- 各关节运动方向
- 各关节安全范围
- 夹爪完全张开位置
- 夹爪完全闭合位置

## 7. 主从遥操作

### 7.1 基本流程

```text
人工移动 Leader
→ 读取 Leader 关节状态
→ 映射为 Follower 目标动作
→ 执行动作限幅
→ 下发给 Follower
→ 读取 Follower 实际状态
```

### 7.2 验收标准

- Leader 与 Follower 对应关节方向一致
- 夹爪映射正确
- 无关节超限
- 无明显异常抖动
- 无持续通信丢失
- 能够连续运行
- 可以安全停止
- 断线后不会继续执行危险动作

### 7.3 需要重点记录

- 控制频率
- 单次循环延迟
- 串口稳定性
- 动作限幅方式
- 丢包处理方式
- 超时处理方式
- 舵机异常处理方式

## 8. 摄像头配置

本项目使用两路摄像头：

- 第一视角腕部摄像头
- 第三视角固定摄像头

### 8.1 第一视角摄像头

优势：

- 接近夹爪和目标
- 适合观察抓取位置
- 适合精细对齐
- 可以补充局部操作信息

风险：

- 运动模糊
- 机械臂抖动
- 夹爪遮挡
- 视野范围较小
- 图像随机械臂运动而变化

### 8.2 第三视角摄像头

优势：

- 提供稳定全局视野
- 能观察整个工作区
- 能同时观察目标与放置区
- 适合任务结果验证
- 适合录制完整演示视频

### 8.3 需要确认

- 摄像头设备编号
- 摄像头稳定标识
- 分辨率
- FPS
- 图像格式
- 时间戳
- 图像是否同步
- 断帧处理
- ACT 使用哪些视角

## 9. 演示数据集

### 9.1 每个 Episode 应包含

- 任务描述
- Follower 关节 Observation
- 第一视角图像
- 第三视角图像
- Leader 产生的 Action
- 时间戳
- Episode 起点
- Episode 终点
- 元数据
- 成功或失败状态

### 9.2 高质量数据要求

- 演示必须成功
- 机械臂动作平滑
- 任务定义一致
- 摄像头位置固定
- 工作区背景稳定
- Episode 起止边界清楚
- 初始位置具有一定多样性
- 避免无意义晃动
- 避免遮挡关键目标
- 避免动作过快

### 9.3 数据检查项

- 图像是否缺帧
- 图像与关节是否同步
- Action 是否超限
- Episode 是否完整
- 失败 Episode 是否被删除
- 任务描述是否一致
- 数据保存路径是否明确
- 数据集版本是否可追踪

## 10. ACT 行为克隆

### 10.1 ACT 的作用

ACT 从机器人 Observation 预测未来一段 Action 序列。

可能输入：

- 机器人关节状态
- 第一视角图像
- 第三视角图像
- 任务信息

输出：

- 一段未来动作序列，即 Action Chunk

### 10.2 为什么预测 Action Chunk

相比每一步只预测一个动作，Action Chunk 可以：

- 降低长时间 Rollout 中的误差累积
- 提高动作连贯性
- 更适合短时操作技能
- 减少高频推理压力

### 10.3 本项目重点关注

- `chunk_size`
- 图像输入尺寸
- 摄像头数量
- Batch Size
- 学习率
- 训练步数
- Checkpoint 保存
- 推理频率
- 动作平滑
- 真实 Rollout 安全

### 10.4 常见失败原因

- 演示数据数量不足
- 演示动作不一致
- 摄像头视角变化
- 起始状态偏离训练分布
- 光照变化
- 目标位置变化过大
- 动作误差逐步累积
- 夹爪接触失败
- 舵机回差
- 实际控制频率与训练数据不一致

## 11. 真实机械臂 Rollout

### 11.1 安全检查

- 使用低速模式
- 首次运行时清空工作区
- 人员必须在场
- 手保持在急停或断电位置附近
- 启用关节限位
- 启用工作空间限制
- 启用 Action Clipping
- 设置最大 Episode 时长
- 异常动作立即停止
- 禁止无人值守运行

### 11.2 执行记录

每次 Rollout 需要记录：

- Checkpoint
- 任务描述
- 初始物体位置
- 执行时间
- 是否成功
- 是否人工干预
- 失败发生阶段
- 摄像头录像
- 机器人状态日志

## 12. 项目评估指标

- 抓取成功率
- 放置成功率
- 端到端任务成功率
- 平均任务完成时间
- 人工干预次数
- 位置误差
- 通信异常次数
- Episode 超时次数
- 策略失败类型

失败类别示例：

- 未识别目标
- 抓取位置错误
- 夹爪没有夹紧
- 物体滑落
- 目标区域判断错误
- 摄像头遮挡
- 舵机通信失败
- 关节越界
- Policy 动作漂移
- 光照变化导致视觉失效

## 13. Agent 接入边界

LLM Agent 负责：

- 自然语言任务理解
- 高层技能选择
- 技能执行顺序
- 工具调用
- 失败后的有限重试决策
- 任务结果总结

LLM Agent 不负责：

- 原始舵机值生成
- 高频关节控制
- 未校验轨迹生成
- 绕过安全限制
- 直接控制急停逻辑

建议工具接口：

```text
detect_target()
get_robot_state()
execute_pick()
execute_place()
verify_task()
emergency_stop()
```

推荐分层：

```text
LLM Agent
→ 高层机器人技能
→ 安全检查
→ Policy 或控制器
→ 机械臂
```

## 14. 上游 LeRobot 与厂商版本差异

### 上游 LeRobot

特点：

- 跟随官方最新架构
- Python 和 PyTorch 版本可能较新
- 官方 SO-101 使用上游硬件实现
- 文档与命令更新较快

### 厂商版本

特点：

- 使用 HX 系列舵机
- 使用幻尔总线驱动模块
- 可能包含厂商硬件适配代码
- 可能固定 LeRobot 版本
- 可能固定 Python 与 FFmpeg 版本
- 不应直接套用所有上游 SO-101 命令

### 当前策略

```text
优先跑通厂商版本
→ 完成机械臂标定
→ 完成主从遥操作
→ 完成双摄像头预览
→ 完成数据录制
→ 完成 ACT 训练
→ 完成真实推理
→ 再评估上游迁移
```

## 15. 当前已理解内容

1. LeRobot 用统一接口连接 Robot、Teleoperator、Camera、Dataset 和 Policy。
2. Leader 主要负责人工示教，Follower 主要负责动作执行。
3. 标定是连接硬件控制、数据录制和策略部署的基础。
4. ACT 通过 Action Chunk 提高短时操作任务的动作连贯性。
5. LLM Agent 应只负责高层任务规划，不直接承担底层关节控制。
